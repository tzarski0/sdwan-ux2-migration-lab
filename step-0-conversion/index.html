Step 0: Configuration Conversion¶

Before a device can move to UX 2.0, its configuration has to exist in UX 2.0 form. Configuration conversion means translating UX 1.0 objects (device templates, feature templates and policies) into their UX 2.0 equivalents.

This step is already done for you

Conversion can take a lot of time in a real network, and it is a separate topic from migrating devices. To keep this lab focused on the migration (moving routers from UX 1.0 to UX 2.0 safely, one site at a time), the lab starts with the configuration already converted. There is nothing to configure in this step. Read it for background, then continue to Step 1.

How UX 1.0 maps to UX 2.0¶

UX 1.0 UX 2.0
Device template Configuration group
Feature templates Features inside feature profiles (System, Transport & Management, Service, CLI Add-on)
Device-specific variables (template CSV) Variables filled in when the configuration group is deployed
Localized policy (QoS, application visibility) and centralized data policy Policy group (for example with an Application Priority & SLA policy)
Centralized control policy (for example hub-and-spoke) Topology policy
Site lists (ranges of site IDs) Network hierarchy (sites and groups)

What is already converted in this lab¶

UX 1.0 object UX 2.0 object already in SD-WAN Manager
Device template dc Configuration group dc (profiles system, transport, bgp_lan, cli)
Device template branch Configuration group branches (profiles system, transport, ospf_lan, cli)
QoS, application visibility and data policy Policy group policy_group with Application Priority policy app_priority

You will build the remaining pieces yourself, because they are central to the migration: the network hierarchy in Step 2 and the topology policy in Step 4.

Approaches to conversion¶

Organizations usually take one of two approaches:

  • Lean option

    Use the Cisco-provided configuration conversion tool, which converts UX 1.0 to UX 2.0 one-to-one. Fast, and the result closely matches what is running today, including any legacy configuration. Learn more about the tool.

  • Power option

    Build the UX 2.0 configuration from scratch. This takes more effort, but it is a chance to remove legacy configuration that is no longer needed and to reduce the number of configuration groups and policy groups.

Mix and match

You can also combine the options: convert all configuration automatically first, then optimize it before assigning it to devices.
