Step 2: Define the Site Hierarchy¶

Why the network hierarchy matters¶

In UX 1.0, centralized policies identify sites through site lists, which are ranges of site IDs typed by hand (for example branches = 20-99). In UX 2.0, SD-WAN Manager uses the network hierarchy instead: a tree of groups and sites below Global, where each site has a name, a site ID and a location.

UX 2.0 features such as topology policies refer to sites and groups in the hierarchy instead of to raw site ID ranges. A well-designed hierarchy means that:

  • policies stay readable, for example "apply hub-and-spoke to group branches",
  • a new site gets the right policy simply by being placed in the right group,
  • devices are deployed to a named site rather than to a bare number.

Why new site IDs?

In this lab, every migrated site gets a new site ID (DC 10 → 110, branches 2x → 12x). The existing UX 1.0 policy matches the old IDs and the new UX 2.0 topology matches the new sites, so a router moves from one policy to the other simply by changing its site ID. This lets you migrate one site at a time while both policies run side by side.

SD-WAN Manager has already created sites such as SITE_10 and SITE_21 automatically from the site IDs of existing devices.

Tasks¶

  • Go to Configuration → Network Hierarchy. Click … next to Global and select Add Site.

  • Create a site with these values, then click Add:

    Name Site ID Address
    dc 110 Oslo

  • Click … next to Global again and select Add Node.

  • Create a new Group named branches.

  • Click … next to group branches and select Add Site.

  • Create a site with these values, then click Add:

    Name Site ID Address
    Bergen 121 Bergen

  • Follow the same steps to add two more sites to group branches:

    Name Site ID Address
    Tromso 122 Tromsø
    Trondheim 123 Trondheim
