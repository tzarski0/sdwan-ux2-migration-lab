SD-WAN UX 1.0 to UX 2.0 Migration Lab¶

This lab walks through moving Catalyst SD-WAN devices from UX 1.0 configuration (device templates and centralized policy) to UX 2.0 configuration (configuration groups, policy groups and topology policies).

There are many ways to migrate from UX 1.0 to UX 2.0. This lab explores one of them, a one-by-one (site-by-site) migration. Each organization should evaluate the options and choose the approach that fits it best.

Lab topology¶

The lab network has one data center and three branches, connected over two transports: INET and MPLS. Every SD-WAN edge router has one link to each transport.

Site Routers System IPs Site ID (UX 1.0) LAN LAN routing
Data Center dc-edge1, dc-edge2 10.0.0.11, 10.0.0.12 10 192.168.10.0/30 (dc-edge1), 192.168.10.4/30 (dc-edge2) BGP to dc-core
Branch 1 br1-edge 10.0.0.21 21 192.168.21.0/24 OSPF to br1-core
Branch 2 br2-edge 10.0.0.22 22 192.168.22.0/24 OSPF to br2-core
Branch 3 br3-edge 10.0.0.23 23 192.168.23.0/24 OSPF to br3-core

Addresses for testing

To test reachability across the overlay (for example with ping or traceroute from the core routers in CML), use these addresses:

Router Test address
dc-core 192.168.10.10 (Loopback)
br1-core 192.168.21.2
br2-core 192.168.22.2
br3-core 192.168.23.2

The control components (SD-WAN Manager, Validator and two Controllers) are at site 100 and reach the transports through the VPN0 and Gateway routers.

Hub-and-spoke¶

The overlay runs in a hub-and-spoke topology:

  • The DC routers are the hubs. The centralized control policy only lets branches learn TLOCs and routes from the DC site.
  • The branches are the spokes. They build data-plane tunnels only to the DC, not to each other, so branch-to-branch traffic goes through the DC.

This policy is the main thing to keep working during the migration. Steps 3 and 4 make sure branches keep reaching the DC whether a site is still on UX 1.0 or already on UX 2.0.

What you will do¶

Time: 60 minutes

Steps 1 to 5 are the core lab. Steps 6 and 7 are optional if you have time left.

Step Task
0 Understand how UX 1.0 configuration is converted to UX 2.0 Reading only
1 Verify the current network state Core
2 Define the network (site) hierarchy Core
3 Update the UX 1.0 centralized policy to support the new site IDs Core
4 Define the UX 2.0 topology policy Core
5 Migrate the DC routers from UX 1.0 to UX 2.0 Core
6 Migrate the branch routers from UX 1.0 to UX 2.0 Optional
7 Clean up UX 1.0 configuration Optional

Lab access¶

  1. Open the lab link shared by your proctor to get a pod assigned.

  2. In dCloud, click Jumphost, then under Remote Access click Web RDP.

  3. On the jumphost, open Chrome and use the bookmarks to open SD-WAN Manager and CML.

Credentials

Your proctor shares the credentials for the jumphost, SD-WAN Manager and CML separately.
